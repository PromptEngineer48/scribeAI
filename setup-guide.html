Deploy ScribeAI to Hostinger

This guide walks you through deploying the complete ScribeAI stack to a Hostinger VPS — from purchasing the server to a live, SSL-secured API with billing. Estimated setup time: 45–90 minutes.

Server
Hostinger KVM 2
2 vCPU · 8 GB RAM · $14/mo
OS
Ubuntu 22.04 LTS
Minimal server image
Stack
FastAPI + Supabase
Python 3.11 · Nginx · PM2
ℹ️

You'll need: a Hostinger account, a domain name (can be purchased through Hostinger), a Supabase account (free tier works), a Lemon Squeezy account (for billing), and your ScribeAI GitHub repo.

01
// hostinger setup

Purchase & Configure Your Hostinger VPS

ScribeAI requires a VPS (Virtual Private Server) — not shared hosting. Hostinger's KVM plans give you full root access, which is required to run FastAPI, Nginx, and PM2.

1.1 — Purchase the VPS

  • 1Go to hostinger.com → VPS Hosting. Select KVM 2 (2 vCPU, 8 GB RAM) — this is sufficient for a production ScribeAI deployment.
  • 2Choose Ubuntu 22.04 LTS as the operating system. Do not choose other distributions.
  • 3Choose a datacenter region close to your primary users. For India/Asia: Singapore. For US users: US East.
  • 4Complete checkout. Your VPS will be provisioned within 2–5 minutes.

1.2 — Get Your Server IP & SSH Access

After provisioning, go to hPanel → VPS → Manage. You'll see your server IP address and the root password Hostinger generated.

⚠️

Save your root password from hPanel immediately. Hostinger only shows it once. If you lose it, you'll need to use hPanel's emergency console to reset it.

1.3 — First SSH Login

# Connect to your server (replace with your actual IP)
ssh root@YOUR_SERVER_IP

# You'll be prompted to change the root password on first login
# Enter the Hostinger-generated password, then set a new strong password

1.4 — Set Up SSH Key Authentication (Recommended)

# On your LOCAL machine — generate a key pair if you don't have one
ssh-keygen -t ed25519 -C "scribeai-vps"

# Copy your public key to the server
ssh-copy-id root@YOUR_SERVER_IP

# Now you can SSH without a password
ssh root@YOUR_SERVER_IP

Install All Dependencies

Run this entire block as one command after SSH-ing into your VPS. It installs Python, Node.js, Nginx, Certbot, and PM2 in a single pass.

# Update system packages
apt update && apt upgrade -y

# Install core tools
apt install -y python3-pip python3-venv git nginx certbot python3-certbot-nginx curl unzip

# Install Node.js 20 (LTS)
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs

# Install PM2 globally
npm install -g pm2

# Verify installations
python3 --version   # Should be 3.10+
node --version      # Should be v20.x
pm2 --version       # Should be 5.x
nginx -v            # Should be nginx/1.18+
✅

You should see version numbers for all four tools. If any fail, re-run the specific install command for that tool.

GitHub Authentication (Personal Access Token)

GitHub no longer accepts password authentication. Use a Personal Access Token (PAT) when cloning private repos or pushing changes.

  • 1Go to github.com → Profile → Settings → Developer Settings → Personal access tokens → Tokens (classic).
  • 2Click Generate new token. Select scope: repo. Copy the token immediately.
  • 3Use the token in your clone URL: https://YOUR_TOKEN@github.com/username/scribeai.git

Supabase: Database, Auth & Storage

Supabase provides the PostgreSQL database, user authentication, and file storage for ScribeAI. The free tier is sufficient to start.

4.1 — Create the Supabase Project

  • 1Go to supabase.com → New Project. Name it scribeai.
  • 2Select region: Southeast Asia (Singapore) for lowest latency if your server is in Singapore.
  • 3Set a strong database password. Save it — you won't see it again.

4.2 — Enable Email Authentication

Go to Authentication → Sign In / Providers → Email and enable it. This allows users to sign up with email + password via Supabase Auth.

4.3 — Get Your Keys

Go to Settings → Integrations → Data API. Copy the Project URL (ends in .supabase.co).

Go to Settings → API Keys → Legacy API keys tab. Copy the service_role key.

🚨

Always use the service_role key in your backend — never the anon key. The service_role key bypasses Row Level Security (RLS) so your server can write to the database. Never expose it in client-side code.

4.4 — Create Database Tables

Go to SQL Editor → New Query and run this SQL:

-- API keys table: ties users to their quota and plan
CREATE TABLE api_keys (
  id           UUID    DEFAULT gen_random_uuid() PRIMARY KEY,
  email        TEXT    UNIQUE NOT NULL,
  api_key      TEXT    UNIQUE NOT NULL,
  user_id      UUID    REFERENCES auth.users(id),
  plan         TEXT    DEFAULT 'hobby',
  tokens_limit INTEGER DEFAULT 50000,
  tokens_used  NUMERIC DEFAULT 0,
  created_at   TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_api_keys_user_id ON api_keys(user_id);
CREATE INDEX idx_api_keys_key ON api_keys(api_key);

-- Generation history log
CREATE TABLE generations (
  id               BIGSERIAL     PRIMARY KEY,
  api_key          TEXT          NOT NULL,
  generation_id    TEXT          NOT NULL,
  content_type     TEXT          NOT NULL,
  topic            TEXT,
  content          TEXT,
  tokens_used      INTEGER DEFAULT 0,
  model            TEXT,
  latency_ms       INTEGER,
  created_at       TIMESTAMPTZ   NOT NULL DEFAULT now()
);

CREATE INDEX idx_generations_api_key ON generations(api_key);

4.5 — Enable Row Level Security (RLS)

-- Enable RLS on both tables
ALTER TABLE api_keys ENABLE ROW LEVEL SECURITY;
ALTER TABLE generations ENABLE ROW LEVEL SECURITY;

-- Users can only read/insert their own API key
CREATE POLICY "user_own_key_select" ON api_keys
  FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY "user_own_key_insert" ON api_keys
  FOR INSERT WITH CHECK (auth.uid() = user_id);

-- Users can only see their own generations
CREATE POLICY "user_own_gens" ON generations
  FOR SELECT USING (
    api_key IN (SELECT api_key FROM api_keys WHERE user_id = auth.uid())
  );

4.6 — Create the Token Counter Function

-- RPC function to safely increment token usage
CREATE OR REPLACE FUNCTION increment_tokens_used(key_val TEXT, delta INT)
RETURNS VOID AS $$
BEGIN
  UPDATE api_keys
  SET tokens_used = tokens_used + delta
  WHERE api_key = key_val;
END;
$$ LANGUAGE plpgsql;

Create the .env Configuration File

The .env file stores all secrets. It is never committed to GitHub. Create it manually on the server.

nano /var/www/scribeai/.env

Paste this content and fill in each value:

SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_KEY=eyJhbGciOi...your-service-role-key
SUPABASE_JWT_SECRET=your-legacy-jwt-secret-here

OPENAI_API_KEY=sk-proj-your-openai-key-here

Configure Nginx & Install SSL Certificate

6.1 — Create the Nginx Config File

nano /etc/nginx/sites-available/scribeai

Paste this config (replace yourdomain.com with your actual domain):

server {
    server_name yourdomain.com www.yourdomain.com;

    # Increase body size limit for any future file uploads
    client_max_body_size 10M;

    location / {
        proxy_pass          http://127.0.0.1:8000;
        proxy_http_version  1.1;
        proxy_set_header    Upgrade $http_upgrade;
        proxy_set_header    Connection 'upgrade';
        proxy_set_header    Host $host;
        proxy_set_header    X-Real-IP $remote_addr;
        proxy_set_header    X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_cache_bypass  $http_upgrade;
        proxy_read_timeout  120s;
        proxy_connect_timeout 120s;
    }
}

6.2 — Enable the Site & Test Config

# Create symlink to enable the site
ln -s /etc/nginx/sites-available/scribeai /etc/nginx/sites-enabled/

# Remove default site if it exists
rm -f /etc/nginx/sites-enabled/default

# Test config syntax
nginx -t
# Should output: configuration file /etc/nginx/nginx.conf syntax is ok

# Restart Nginx
systemctl restart nginx
systemctl enable nginx

6.3 — Install SSL with Certbot

⚠️

Your domain's DNS must be pointing to your server IP before running Certbot. See Stage 9 for DNS setup instructions.

# Run Certbot — it auto-detects your Nginx config
certbot --nginx -d yourdomain.com -d www.yourdomain.com

# Follow the prompts:
# - Enter your email address
# - Agree to terms of service
# - Choose whether to redirect HTTP → HTTPS (choose YES)

# Verify auto-renewal works
certbot renew --dry-run
✅

After Certbot finishes, your site will be accessible via https://yourdomain.com. SSL auto-renews every 90 days.

Launch the App with PM2

PM2 keeps your FastAPI server running as a background process, auto-restarts it on crashes, and survives server reboots.

# Navigate to the project and activate venv
cd /var/www/scribeai
source venv/bin/activate

# Start the FastAPI app with PM2
pm2 start "uvicorn server:app --host 127.0.0.1 --port 8000" \
     --name scribeai-api

# Save PM2 process list (persists across reboots)
pm2 save

# Enable PM2 to start on system boot
pm2 startup
# Copy and run the command PM2 outputs — it will look like:
# sudo env PATH=$PATH:/usr/bin pm2 startup systemd -u root --hp /root

Useful PM2 Commands

pm2 status                    # Check all processes
pm2 logs scribeai-api          # View live logs
pm2 logs scribeai-api --lines 100  # View last 100 lines
pm2 restart scribeai-api      # Restart the app
pm2 stop scribeai-api         # Stop the app
pm2 delete scribeai-api       # Remove from PM2

Test the API is Live

curl https://yourdomain.com/health
# Expected: {"status": "ok", "version": "2.1"}

curl -X POST https://yourdomain.com/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email": "test@example.com"}'
# Expected: {"email": "...", "api_key": "sk_live_xxxx", "plan": "hobby"}

// domain setup

Point Your Domain to Hostinger

Option A — Domain purchased through Hostinger (easiest)

If you bought your domain through Hostinger, it's automatically managed in hPanel. Go to hPanel → Domains → DNS / Nameservers and add:

# In Hostinger hPanel → Domains → DNS Zone
# Add these two A records:

Type  Name  Value                    TTL
A     @     YOUR_VPS_IP_ADDRESS      3600
A     www   YOUR_VPS_IP_ADDRESS      3600

Option B — Domain from another registrar (Namecheap, GoDaddy, etc.)

Log into your domain registrar and update the nameservers to point to Hostinger, or add A records directly:

  • 1Log into your registrar's DNS management panel.
  • 2Find the A records section. Delete any existing A records pointing to old servers.
  • 3Add: A @ YOUR_VPS_IP and A www YOUR_VPS_IP
  • 4DNS propagation takes 5 minutes to 48 hours. You can check with: nslookup yourdomain.com
⏱️

Once DNS propagates, run Certbot (Stage 6.3) to get your SSL certificate. The order matters — DNS must resolve to your server before Certbot can verify domain ownership.

Troubleshooting Common Issues

502 Bad Gateway from Nginx

The FastAPI server is not running or crashed. Check PM2:

pm2 status
pm2 logs scribeai-api --lines 50
# If stopped, restart:
pm2 restart scribeai-api

Registration returns 500 or silent error

Almost always a database issue. Check: is the SUPABASE_URL the correct URL from Supabase dashboard? Does it end in .supabase.co (not .supabase.com)? Is the service_role key correct?

# Test Supabase connection from the server
source venv/bin/activate
python3 -c "from supabase import create_client; import os; from dotenv import load_dotenv; load_dotenv(); c = create_client(os.getenv('SUPABASE_URL'), os.getenv('SUPABASE_KEY')); print(c.table('api_keys').select('id').limit(1).execute())"

Certbot SSL fails ("Domain not resolved")

DNS hasn't propagated yet, or the A records are incorrect. Verify with:

nslookup yourdomain.com
# The IP shown should match your VPS IP

git push returns 403

GitHub no longer accepts password auth. Set your remote URL to include your Personal Access Token:

git remote set-url origin https://YOUR_TOKEN@github.com/username/scribeai.git

API key generation broken (NOT NULL violation)

The key generation function in your code is not creating the api_key field before inserting. Ensure your registration function generates the key as: import uuid; key = "sk_live_" + uuid.uuid4().hex
